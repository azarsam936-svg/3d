# فلش‌کارت سه‌بعدی چشم — واقعیت افزوده (WebAR)

این یک پروژه‌ی کاملاً استاتیک است (بدون npm، بدون Node.js، بدون build) که با
**MindAR Image Tracking** (مبتنی بر Three.js از طریق A-Frame) کار می‌کند و
مستقیماً روی **GitHub Pages** قابل میزبانی است.

> **چرا A-Frame به‌جای نوشتن دستی با Three.js خام؟**
> A-Frame یک لایه‌ی نازک و بسیار پایدار روی Three.js است و رسمی‌ترین و
> مطمئن‌ترین راه یکپارچه‌سازی MindAR برای هاست استاتیک (بدون build) همین است.
> نتیجه‌ی نهایی از نظر کاربر دقیقاً همان چیزی‌ست که خواسته شده (ردیابی تصویر
> واقعی، نه فقط QR)، اما پایدارتر و کم‌خطاتر از نوشتن دستی pipeline خام
> Three.js + MindAR است. تمام مقادیر Scale/Position/Rotation هم‌چنان با چند
> متغیر ساده در بالای `script.js` قابل ویرایش هستند.

---

## ۱) ساختار پروژه

```
/
├── index.html
├── style.css
├── script.js
├── README.md
└── assets/
    ├── u.glb                 ← فایل مدل سه‌بعدی چشم (باید خودت اضافه کنی)
    ├── targets.mind          ← فایل هدفِ کامپایل‌شده (باید خودت بسازی — پایین توضیح داده شده)
    ├── eye-marker.png        ← مارکر ردیابی برای چاپ روی فلش‌کارت (آماده)
    └── eye-marker-print.png  ← نسخه‌ی چاپی با حاشیه‌ی سفید (آماده)
```

---

## ۲) فایل مدل سه‌بعدی (u.glb) را کجا بگذارم؟

فایل مدل چشم خودت را با نام دقیق **`u.glb`** داخل پوشه‌ی `assets/` قرار بده:

```
assets/u.glb
```

اگر نام فایل یا مسیر را تغییر دادی، باید در `index.html` خط زیر را هم به‌روزرسانی کنی:

```html
<a-asset-item id="eye-model" src="assets/u.glb"></a-asset-item>
```

## ۳) مارکر ردیابی (تصویر روی فلش‌کارت)

**نکته‌ی مهم:** این مارکر یک QR کد معمولی نیست؛ یک تصویر پرجزئیات و
غیرمتقارن است که مخصوص ردیابی تصویر (image tracking) طراحی شده تا دوربین
بتواند موقعیت و چرخش دقیق فلش‌کارت را در فضای سه‌بعدی تشخیص دهد.

دو فایل برایت آماده شده:

- **`assets/eye-marker.png`** → همین فایل باید هنگام ساخت `targets.mind`
  به‌عنوان تصویر هدف (target image) استفاده شود.
- **`assets/eye-marker-print.png`** → نسخه‌ی آماده‌ی چاپ با حاشیه‌ی سفید کافی
  و خط‌های راهنمای برش دور آن — همین فایل را چاپ کن.

### توصیه‌های چاپ

| مورد | توصیه |
|---|---|
| اندازه‌ی فیزیکی مارکر | ۵ تا ۸ سانتی‌متر (مربع) — نه کوچک‌تر از ۴ سانتی‌متر |
| نوع کاغذ | مات (Matte) — از کاغذ براق یا گلاسه پرهیز کن، بازتاب نور ردیابی را خراب می‌کند |
| کنتراست چاپ | چاپ رنگی با کیفیت بالا؛ اگر چاپ سیاه‌وسفید داری، حتماً کنتراست را در تنظیمات چاپگر بالا ببر |
| صافی سطح | فلش‌کارت باید صاف باشد؛ چروک یا خم‌شدگی دقت ردیابی را کم می‌کند |
| روکش | از روکش گلاسه‌ی ضخیم یا سلفون براق پرهیز کن؛ اگر روکش لازم است از نوع مات استفاده کن |
| حاشیه | حداقل ۱ سانتی‌متر حاشیه‌ی سفید دور مارکر نگه دار (در فایل print از قبل رعایت شده) |

## ۴) ساخت فایل targets.mind (مهم‌ترین مرحله)

فایل `assets/targets.mind` در این پروژه فقط یک **جایگزین (placeholder)** است
و کار نمی‌کند — باید خودت آن را با ابزار رسمی MindAR بسازی. این کار نیازی به
نصب چیزی ندارد و کاملاً در مرورگر انجام می‌شود:

1. به آدرس زیر برو (کامپایلر آنلاین رسمی MindAR):
   **https://hiukim.github.io/mind-ar-js-doc/tools/compile**
2. فایل **`assets/eye-marker.png`** را در آن صفحه آپلود کن.
3. دکمه‌ی **Start** را بزن و صبر کن تا پردازش تمام شود.
4. فایل خروجی را با نام **`targets.mind`** دانلود کن.
5. آن را داخل پوشه‌ی `assets/` پروژه بگذار و فایل placeholder فعلی را
   جایگزین کن:

```
assets/targets.mind
```

> اگر چند فلش‌کارت داری (مثلاً چشم + سلول گیاهی)، می‌توانی همه‌ی تصاویر
> مارکر را با هم در همان صفحه آپلود کنی تا یک `targets.mind` واحد با چند
> هدف (multi-target) بسازی. ترتیب آپلود، شماره‌ی `targetIndex` هرکدام را
> مشخص می‌کند (اولین تصویر = ۰، دومین = ۱ و...). بخش «افزودن فلش‌کارت جدید»
> در پایین همین فایل را ببین.

## ۵) آپلود پروژه در گیت‌هاب و فعال‌سازی GitHub Pages

1. یک ریپازیتوری جدید در GitHub بساز (مثلاً `eye-flashcard-ar`).
2. تمام فایل‌های این پروژه (شامل پوشه‌ی `assets` با `u.glb` و `targets.mind`
   واقعی) را در همان ریپازیتوری آپلود کن (از طریق وب‌سایت GitHub، دکمه‌ی
   «Add file → Upload files»، یا با Git).
3. وارد **Settings → Pages** ریپازیتوری شو.
4. در بخش **Source**، گزینه‌ی **Deploy from a branch** را انتخاب کن.
5. شاخه (Branch) را روی `main` (یا `master`) و پوشه را روی `/ (root)` بگذار
   و **Save** کن.
6. بعد از حدود یک تا دو دقیقه، آدرسی شبیه این فعال می‌شود:

```
https://USERNAME.github.io/eye-flashcard-ar/
```

## ۶) باز کردن روی گوشی و دادن دسترسی دوربین

1. آدرس بالا را روی گوشی (اندروید با Chrome، یا آیفون با Safari) باز کن —
   حتماً باید **HTTPS** باشد (GitHub Pages به‌طور پیش‌فرض HTTPS می‌دهد).
2. مرورگر یک پیام برای درخواست دسترسی به دوربین نشان می‌دهد؛ گزینه‌ی
   **Allow / اجازه بده** را بزن.
3. اگر اشتباهی دسترسی را رد کردی: وارد تنظیمات مرورگر → تنظیمات سایت
   (Site settings) شو، سایت را پیدا کن و دسترسی دوربین را روی «Allow» بگذار،
   سپس صفحه را رفرش کن.
4. فلش‌کارت (روی همان صفحه‌ی چاپی `eye-marker-print.png`) را مقابل دوربین
   عقب بگیر تا مدل سه‌بعدی چشم روی آن ظاهر شود.

## ۷) تغییر مقیاس و موقعیت مدل

بالای فایل **`script.js`** این متغیرها را پیدا می‌کنی:

```js
const MODEL_SCALE = 0.05;
const MODEL_POSITION_X = 0;
const MODEL_POSITION_Y = 0.15;
const MODEL_POSITION_Z = 0;
const MODEL_ROTATION_X = -90;
const MODEL_ROTATION_Y = 0;
const MODEL_ROTATION_Z = 0;
```

- **MODEL_SCALE**: بزرگ یا کوچک کردن یکنواخت مدل. عدد بزرگ‌تر = مدل بزرگ‌تر.
- **MODEL_POSITION_X/Y/Z**: جابه‌جایی مدل نسبت به مرکز فلش‌کارت
  (Y = ارتفاع بالای کارت).
- **MODEL_ROTATION_X/Y/Z**: چرخش مدل بر حسب درجه — اگر مدل «خوابیده» یا
  «وارونه» ظاهر شد، معمولاً تغییر `MODEL_ROTATION_X` بین `90` و `-90` مشکل
  را حل می‌کند.

بعد از تغییر عدد، فایل را ذخیره کن، دوباره آپلود کن (یا اگر لوکال تست
می‌کنی، صفحه را رفرش کن) و نتیجه را روی فلش‌کارت ببین.

همچنین یک دکمه‌ی **«بازنشانی مدل»** پایین صفحه هست که موقعیت/مقیاس مدل را
به همین مقادیر پیش‌فرض برمی‌گرداند (برای مواقعی که در آینده کنترل‌های
تعاملی برای جابه‌جایی مدل اضافه کردی).

## ۸) افزودن فلش‌کارت جدید (سلول گیاهی، قلب، مغز، ...)

این پروژه طوری ساخته شده که افزودن کارت‌های بیشتر ساده باشد:

1. یک مارکر جدید و پرجزئیات برای موضوع جدید طراحی/آماده کن (شبیه
   `eye-marker.png` — پرکنتراست، نامتقارن، بدون نواحی خالی بزرگ).
2. آن تصویر را همراه `eye-marker.png` در همان کامپایلر آنلاین MindAR
   (بخش ۴ همین فایل) آپلود کن تا یک `targets.mind` جدید با چند هدف بسازی.
3. فایل `targets.mind` جدید را جایگزین فایل فعلی کن.
4. مدل GLB جدید را در `assets/` بگذار (مثلاً `assets/plant-cell.glb`).
5. در `index.html`، یک `<a-entity>` جدید مشابه `#eye-target` اضافه کن اما با
   `targetIndex` متفاوت (بر اساس ترتیب آپلود در کامپایلر):

```html
<a-entity id="plant-cell-target" mindar-image-target="targetIndex: 1">
  <a-entity gltf-model="#plant-cell-model" scale="0.04 0.04 0.04" ...></a-entity>
</a-entity>
```

6. یک `<a-asset-item>` جدید هم داخل `<a-assets>` برای مدل جدید اضافه کن.
7. در `script.js`، یک ورودی جدید به `CARD_REGISTRY` اضافه کن (نمونه‌ی آن
   داخل کامنت‌های همان فایل موجود است) تا مدیریت مقادیر پیش‌فرض راحت باشد.

## ۹) پیام‌های خطا (به‌صورت خودکار در برنامه نمایش داده می‌شوند)

| وضعیت | پیام |
|---|---|
| دسترسی دوربین رد شد | راهنمای فارسی برای فعال‌کردن دسترسی از تنظیمات مرورگر |
| مرورگر از AR پشتیبانی نمی‌کند | «این مرورگر از قابلیت واقعیت افزوده پشتیبانی نمی‌کند. لطفاً از Chrome یا Safari استفاده کنید.» |
| مارکر شناسایی نشد | «تصویر فلش‌کارت را مقابل دوربین قرار دهید.» |
| بارگذاری مدل GLB ناموفق بود | پیام راهنما برای بررسی مسیر `assets/u.glb` |

## ۱۰) نکات فنی و عملکردی

- تمام مسیرهای فایل نسبی (relative) هستند؛ هیچ فرضی درباره‌ی `localhost`
  وجود ندارد، پس روی GitHub Pages بدون تغییر کار می‌کند.
- نور محیطی (ambient) و نور جهت‌دار (directional) به‌صورت پیش‌فرض روی مدل
  تنظیم شده تا مدل روی موبایل سیاه یا نامرئی دیده نشود.
- `antialias` و `pixel ratio` مناسب موبایل تنظیم شده تا هم‌زمان کیفیت و
  کارایی حفظ شود.
- اگر مدل GLB سنگین باشد (چند مگابایت بزرگ)، فشرده‌سازی Draco/Meshopt در
  خروجی مدل توصیه می‌شود (مثلاً از طریق Blender هنگام Export گرفتن GLB).

---

## ۱۱) اگر چیزی کار نکرد

- مطمئن شو `assets/u.glb` و `assets/targets.mind` **واقعی** جایگزین
  فایل‌های placeholder شده‌اند (فایل `targets.mind` پیش‌فرض این پروژه فقط
  یک متن راهنماست، نه فایل باینری واقعی).
- مطمئن شو سایت روی HTTPS باز شده (آدرس `github.io` به‌طور پیش‌فرض HTTPS است).
- در گوشی، از آخرین نسخه‌ی Chrome (اندروید) یا Safari (آیفون) استفاده کن.
- نور محیط را بیشتر کن و فلش‌کارت را صاف و بدون چروک مقابل دوربین بگیر.
